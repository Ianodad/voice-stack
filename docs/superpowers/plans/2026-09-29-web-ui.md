# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browser UI (orb, live transcript, mute/push-to-talk, saved resumable history) for the local voice assistant, with browser echo cancellation so barge-in works on speakers.

**Architecture:** Refactor the one-shot `async_main` into `Runtime` (models + `mlx_lm.server`, loaded once) and `bot.build_worker` (per-session pipeline on any transport). A FastAPI `server.py` does WebRTC signaling through Pipecat's `SmallWebRTCRequestHandler`, serves the built Vite frontend, and exposes history REST backed by stdlib SQLite. RTVI (auto-enabled by `PipelineWorker`) carries events to the browser.

**Tech Stack:** pipecat-ai 1.12.0 (`[webrtc]` extra → aiortc), FastAPI + uvicorn, sqlite3, Vite + vanilla TypeScript, `@pipecat-ai/client-js@1.13.1`, `@pipecat-ai/small-webrtc-transport@1.10.8` (peer `client-js ~1.13.0`).

**Spec:** `docs/superpowers/specs/2026-09-27-web-ui-design.md`

## Task-0 gate result (verified 2026-09-29 against installed sources) — WebRTC is viable

- `pipecat.transports.smallwebrtc.{request_handler,transport,connection}` exist. `SmallWebRTCRequestHandler(connection_mode=ConnectionMode.SINGLE)`; `handle_web_request(SmallWebRTCRequest(sdp,type,pc_id,restart_pc,request_data), callback)` returns the SDP answer dict; `handle_patch_request(SmallWebRTCPatchRequest)` for ICE candidates; `close()`.
- `SmallWebRTCTransport(webrtc_connection, params: TransportParams)`; events `on_client_connected`, `on_client_disconnected`, `on_app_message`.
- `pipecat-ai[webrtc]` adds aiortc + opencv-headless; dry-run resolves with fastapi 0.141.1 / uvicorn 0.54.0 and does not touch the `soundfile<0.14` pin.
- `PipelineWorker(..., enable_rtvi=None)` auto-adds RTVI. `RTVIProcessor` event `on_client_message` gives `RTVI.ClientMessage(msg_id, type, data)`.
- client-js events: `userStartedSpeaking`, `userStoppedSpeaking`, `botStartedSpeaking`, `botStoppedSpeaking`, `userTranscript`, `botTtsText`, `botLlmText`, `botOutput`, `localAudioLevel`, `remoteAudioLevel`; `client.enableMic(bool)`, `client.sendClientMessage(type, data)`, `client.connect({webrtcRequestParams:{endpoint}})`.
- **No built-in "interrupt" client call** → Esc uses `sendClientMessage("interrupt")` + a server `on_client_message` handler that queues `InterruptionFrame` (Task 3).
- Aggregator hooks: `user_agg.event_handler("on_user_turn_stopped")` → `(aggregator, strategy, message)`; `assistant_agg.event_handler("on_assistant_turn_stopped")` → `(aggregator, message)`; `message.content`, assistant `message.interrupted`. `LLMContext.set_messages(list)`.

## Global Constraints

- Bind `127.0.0.1` only; no internet after setup; single user; desktop browser only.
- LLM sees system instruction + last **20** stored messages; full history stored/shown.
- Only `user`/`assistant` roles persisted; Pipecat `developer` messages never stored.
- DB at `~/.voice-stack/history.db` (overridable by constructor arg for tests).
- `llm.supports_developer_role = False` and `enable_thinking: False` carried over unchanged.
- SIGINT/SIGTERM must still stop `mlx_lm.server` (no orphan). Web mode does NOT use `AlwaysUserMuteStrategy`.
- All MLX/Metal work stays on the single shared `ThreadPoolExecutor(max_workers=1)`.
- Existing entry points keep working: `voice-stack`, `--barge-in`, `--check`, `scripts/check_stt.py`, `scripts/check_tts.py`.
- Latency no worse than local mode (live LLM TTFB mean 0.43s).

## Review Focus

1. Two tabs / rapid reconnect: second `/api/offer` while a session is live → old worker fully cancelled, no double pipeline on the shared executor, no orphan.
2. `mlx_lm.server` dies mid-session: user turn gets an LLM error → UI error state; that turn not persisted; `/api/llm/restart` recovers without restarting the process.
3. Interrupted bot reply: persist only the spoken text; empty-content assistant turns must NOT be stored (would poison the 20-msg window).
4. Reopen a conversation whose last stored message is a `user` role (crash before reply): context must still be valid for the chat template (no two consecutive same-role errors from Qwen).
5. Server Ctrl-C while a WebRTC session is live: `mlx_lm.server` stopped, SQLite consistent, port released.
